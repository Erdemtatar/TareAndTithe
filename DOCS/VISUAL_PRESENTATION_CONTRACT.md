## 0. Critical Architectural Traps Exposed by C++ Inspection (Read Before Authoring)

1. **Only `LaserSheetMaterial` Is Driven Dynamically at Runtime:**
   - `DefaultMonolithOuterMaterial`, `DefaultMoltenCutCapMaterial`, `CellWallMaterial`, and `CellFloorMaterial` are bound **directly as static `UMaterialInterface*` references** (`SetMaterial` / `ConfigureMaterialSet`) **without** creating a `UMaterialInstanceDynamic` (`MID`). C++ calls **zero** `SetScalarParameterValue` or `SetVectorParameterValue` methods on custom assets in those 4 slots (C++ only creates `MID`s for internal `/Engine/EngineMaterials/FlattenMaterial` greybox fallbacks when custom slots are `nullptr`). Any glow/pulse on `DefaultMoltenCutCapMaterial` must be self-contained in the shader graph (`Time`, UVs) or static `UMaterialInstanceConstant` parameters.
2. **`LaserSheetMaterial` Expands to Full `54 x 58 cm` Cross-Section Upon Assignment:**
   - In greybox mode (`nullptr`), `AInspectorPawn` collapses `LaserSheetVisual` into a `1.6 cm` front guide ribbon so opaque `FlattenMaterial` cannot block the view. Assigning **any** material to `LaserSheetMaterial` (or `/Game/Materials/M_LaserSheet_Master`) switches `bHasCustomTranslucentSheet = true` (`InspectorPawn.cpp:568-585`), scaling two back-to-back planes across the full `54.0 x 58.0 cm` frame right in front of the monolith. **If `LaserSheetMaterial` uses `Blend_Opaque`, it will completely blind the player's view of the monolith.** Use `Blend_Translucent` or `Blend_Additive` and wire `Opacity`.
3. **`FMeshPresentationSlot::ApplyToVisualComponent` Overwrites Component `RelativeTransform`:**
   - When `Mesh != nullptr`, `ApplyToVisualComponent` (`TareTithePresentationDataAsset.cpp:24`) calls `TargetVisualComp->SetRelativeTransform(VisualLocalTransform)` (`FTransform::Identity` by default). Any non-zero C++ greybox `RelativeLocation` on the visual component (`ClampJawVisual` `Z=-2`, `ScaleBaseVisual` `Z=+6`, `DiverterFlapperVisual` `Z=+45.5`, **`TareChuteVisual` `(0, +86, +4)`**) is **wiped to `(0, 0, 0)`** unless baked into mesh pivot space or compensated in `VisualLocalTransform`!
4. **`CellWallPanelMeshSlot` Unrotated 5-Slab Reuse & `GetMaterial(0)` Bypass (`TareTitheGameMode.cpp:266-331`):**
   - When `SpawnGreyboxPitEnclosureAndLighting` runs (only when stations are absent from the map), C++ spawns **all 5 wall/ceiling slabs** (Front, Rear, Left, Right, Ceiling) with **`FRotator::ZeroRotator`** and `(1, 1, 1)` scale when `CellWallPanelMeshSlot.Mesh != nullptr`. Assigning a flat YZ wall mesh into `CellWallPanelMeshSlot.Mesh` will misorient the Left, Right, and Ceiling slabs by `90°`. Leave `CellWallPanelMeshSlot.Mesh = nullptr` (using `CellWallMaterial` on the properly scaled greybox slabs, or hand-placing modular walls in `L_MainGameplay.umap`).
   - Additionally, line 272 checks `if (AssignedSlot->MaterialOverrides.Num() == 0 && IsValid(CustomCellMaterial) && !IsValid(MeshComp->GetMaterial(0)))`. Because every imported `UStaticMesh` carries a default slot 0 material (`WorldGridMaterial` / FBX material), `IsValid(MeshComp->GetMaterial(0))` is `true`, **silently skipping `CellWallMaterial` / `CellFloorMaterial`** when a custom mesh is slotted unless you also assign the material into `Slot.MaterialOverrides[0]` or directly on the `UStaticMesh` asset.
5. **`CustomMonolithMesh` UV0 & Material IDs Are Overwritten on Load (`MonolithSliceComponent.cpp:460-488`):**
   - `InitializeMonolithFromContract` overwrites `UV0` with object-space triplanar `SetMeshUVsFromBoxProjection` (`BoxProjectionUVScaleCm`) and stamps all surface triangles to `MaterialID = 0`. Custom-unwrapped unique 0–1 UV islands/baked normal maps will be destroyed; use tileable/procedural materials on `DefaultMonolithOuterMaterial` (Slot 0) and `DefaultMoltenCutCapMaterial` (Slot 1).

## 3. Custom Sliceable Monolith Requirements (`UMonolithContractDataAsset::CustomMonolithMesh`)

When `UMonolithContractDataAsset::BaseShape == EMonolithBaseShape::CustomStaticMesh`, `UMonolithSliceComponent::InitializeMonolithFromContract` (`MonolithSliceComponent.cpp:402-544`) and `AMonolithRigActor::LoadContractOnRig` (`MonolithRigActor.cpp:265-298`) enforce the following strict geometry contract:

1. **Watertight Closed 2-Manifold Topology (Mandatory):**
   - Copied from `CustomMonolithMesh` LOD 0 (`LODType = MaxAvailable, LODIndex = 0`, `bApplyBuildSettings = true`, `bIgnoreRemoveDegenerates = false`).
   - **Packaged Build Requirement:** Enable **`bAllowCPUAccess = true` (`Allow CPU Access`)** on every `CustomMonolithMesh` `UStaticMesh` asset so GeometryScript can read LOD buffers in cooked builds when Editor `MeshDescription` bulk data is stripped.
   - If `!EditMesh.IsClosed()`, C++ runs `UE::Geometry::FMergeCoincidentMeshEdges` with **`MergeVertexTolerance = 0.001 cm`** (`0.01 mm`) to weld split UV/normal seams.
   - **Hard Validation Gate:** Post-weld mesh MUST satisfy `EditMesh.IsClosed() == true` AND `TriangleCount() >= 4` with **positive outward-facing triangle winding** (`SignedVolume > 0`). Single-sided planes, uncapped holes, non-manifold T-junctions, or self-intersecting shells either **abort to a procedural `EMonolithBaseShape::Box` (`Contract->DimensionsCm`)** or corrupt `TMeshQueries::GetVolumeAreaCenter` analytical mass and `TFastWindingTree` (`Iso = 0.5`) vein containment.
   - **Triangle Budget:** Keep **`<= 3,500` triangles** (`MaxProceduralTriangleBudget = 3500`) to preserve zero-hitch synchronous `FMeshPlaneCut` + Delaunay hole-fill + BVH/FastWinding rebuilds on slice commit.

2. **Local Origin & Bounding-Box Expectations (Use Bounding-Box Center `(0, 0, 0)`):**
   - **Z-Axis Top Alignment (`AMonolithRigActor::LoadContractOnRig`, line 280):** C++ reads `LocalBounds = EditMesh.GetBounds()` and sets `RemainderMeshComponent` relative location to **`(0.0, 0.0, -LocalBounds.Max.Z)`** inside `TiltingMountComponent`. Thus `LocalBounds.Max.Z` is always pulled flush to `TiltingMountComponent` `Z = 0.0 cm`, regardless of Center vs. Bottom pivot.
   - **XY-Axis Torque Coupling (CRITICAL):** C++ sets relative `X = 0.0, Y = 0.0` (it does **NOT** recenter `LocalBounds.Center().X/Y`). Any horizontal offset of the mesh's analytical Center of Mass (`InitialCoMCm.X/Y`) from `(0, 0)` immediately generates real gravity overhang torque $\vec{\tau}_0 = m \vec{r} \times \vec{g}$ on `UClampTorqueSolverComponent` (`ClampTorqueSolverComponent.cpp:248-259`)! Unless designing an intentionally off-balance puzzle contract, center the mesh around `X = 0, Y = 0`.
   - **`HiddenVeins` Coordinate Frame (`UVeinScannerComponent`):** `FVolatileVeinDefinition::LocalStartCm` and `LocalEndCm` are evaluated **directly in `RemainderMeshComponent` (imported `CustomMonolithMesh`) local space**, with zero origin offset! Exporting with **Bounding-Box Center at `(0, 0, 0)`** (`X: [-DimX/2, +DimX/2], Y: [-DimY/2, +DimY/2], Z: [-DimZ/2, +DimZ/2]`) guarantees 1:1 parity with procedural shapes and keeps `HiddenVeins` centered around `Z = 0` inside the volume.
   - **Sync `Contract->DimensionsCm`:** Even when `BaseShape == CustomStaticMesh`, set `Contract->DimensionsCm` (min `5.0 cm` per axis via `IsDataValid`) to match the custom mesh's actual `(X, Y, Z)` bounding box—`DimensionsCm` drives both greybox `ClampJawVisual` XY sizing (`MonolithRigActor.cpp:285-286`) and the procedural `Box` fallback if `CustomMonolithMesh` ever fails watertight validation.

3. **Top-Center Clamp Grip Volume (`ClampGripBoxLocal`):**
   - When `bAutoFitClampGripBoxToTopOfContract == true` (default, `MonolithSliceComponent.cpp:523-534`), C++ computes the grip AABB in mesh-local space:
     - `X`: `BoxCenter.X ± Max(4.0, 0.325 * BoxSize.X)` (`65%` horizontal X coverage)
     - `Y`: `BoxCenter.Y ± Max(4.0, 0.325 * BoxSize.Y)` (`65%` horizontal Y coverage)
     - `Z`: `[InitialLocalBounds.Max.Z - Max(5.0, 0.175 * BoxSize.Z), InitialLocalBounds.Max.Z + 8.0]` (top `17.5%` height)
   - **Rule:** Your custom mesh **MUST contain solid connected geometry inside this top-center `65% XY x 17.5% Z` box**. If the top center is hollow (e.g., an inverted arch or twin spires with a central gap missing `ClampGripBoxLocal`), the first laser slice will classify `bIsGripped = false` on all islands and drop the entire monolith out of the rig.

4. **Physical Cell & Laser Frame Envelope Limits:**
   - **XY Cross-Section:** Keep within **`20.0 .. 48.0 cm` (`X`) x `20.0 .. 52.0 cm` (`Y`)** so the monolith fits cleanly inside the `54.0 x 58.0 cm` laser aiming frame (`AInspectorPawn`) and severed chunks drop unobstructed through the `63.5 cm` hopper throat between `LeftHopperGuideCollider` (`Y = -31.0 cm` inner face) and `DiverterPlateCollider` (`Y = +32.5 cm` inner face).
   - **Z Height:** Keep within **`40.0 .. 105.0 cm`** (`ClampPivotRoot` is at `World Z = 236.0 cm`; vertical `DiverterFlapper` tip sits at `World Z = 155.0 cm` at `Y = +34 cm`, `LeftHopperGuide` top sits at `World Z = 132.0 cm` at `Y = -32.5 cm`, and `45°` Tare ramp reaches `World Z = 128.35 cm` across the throat—heights `<= 100 cm` hang down to `World Z = 136.0 cm`, guaranteeing zero pre-slice collision with the diverter gate!).
   - **Silhouette Orientation (`+X` View):** Extrude asymmetric/stepped features primarily across **`Y` (Left-Right) and `Z` (Up-Down)** facing `-X` so torque-inducing overhangs and bevel angles read clearly from the locked `+X` camera.

5. **Runtime UV & Material Slot Overwrite Behavior:**
   - **UV0:** Replaced on load by `SetMeshUVsFromBoxProjection` at uniform scale `Max(10.0, Contract->BoxProjectionUVScaleCm)` (default `100.0 cm`). Severed chunks translate vertices by `-LocalCoMCm` without re-projecting UVs, preventing texture swimming during freefall.
